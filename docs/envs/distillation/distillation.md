# Distillation Benchmark

## Gymnasium Environment for a Simulated Distillation Column Process

This environment simulates the dynamics of a distillation column process using pre-trained TensorFlow models. The models were trained on synthetic data generated by a gProms (TM) model of the distillation process applied to separate ethanol and water.

## Environment Description

### State Space

The state space of the distillation process is defined as follows.

| Num | Observation                | Min   | Max   |
|-----|----------------------------|-------|-------|
| 0   | Reflux Ratio               | 0.0   | 1.0   |
| 1   | Input Energy Rate          | 0.0   | 1.0   |
| 2   | Mass Flowrate              | 0.0   | 1.0   |
| 3   | Water Fraction             | 0.0   | 1.0   |
| 4   | Ethanol Fraction           | 0.0   | 1.0   |
| 5   | Objective Mass Flowrate    | 0.0   | 1.0   |
| 6   | Objective Water Fraction   | 0.0   | 1.0   |

### Action Space

The system is controlled by the following continuous (floating point) control actions.

| Num | Action                      | Min   | Max   |
|-----|-----------------------------|-------|-------|
| 0   | Control Reflux Ratio        | 0.0   | 1.0   |
| 1   | Control Input Energy Rate   | 0.0   | 1.0   |

### Reward Function

The reward at each step is the sum of two components:

1. Setpoint adherence – the negative absolute deviation of each controlled process variable from its objective, weighted by 1.0:

   ```
   r_setpoint = -1.0 * |Mass Flowrate - Objective Mass Flowrate|
                -1.0 * |Water Fraction - Objective Water Fraction|
   ```

2. Action regularization – a penalty on the 1-step change of each control action, weighted by 0.2:

   ```
   r_action = -0.2 * |Reflux Ratio(t) - Reflux Ratio(t-1)|
              -0.2 * |Input Energy Rate(t) - Input Energy Rate(t-1)|
   ```

The total reward is `r = r_setpoint + r_action`. The maximum achievable reward is 0, attained when all process variables match their objectives and no control action changes are applied.

### Starting State

Depending on the config option "init_method", the starting state is either drawn from a set list
of random initial states ("from_data") or always using the same initial sample provided by the
"initial_observation" option ("fixed").

### Episode End

Depending on the config field "max_episode_steps", the episode is either terminated when the
maximum step limit is reached (default: 100) or is run infinitely (None).
